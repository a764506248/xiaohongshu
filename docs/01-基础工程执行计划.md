# 基础工程执行计划

## 1. 目标

建立可以独立启动、测试和联调的前后端基础工程，为后续业务模块提供稳定底座。本计划不实现 AI 业务功能。

## 2. BE-01：FastAPI 后端基础工程

### 工作范围

- 创建 `backend` Python 工程。
- 建立 FastAPI 应用入口和 `/health` 接口。
- 增加环境配置、日志、请求 ID 和统一异常处理。
- 配置 SQLAlchemy、PostgreSQL 和 Alembic。
- 建立 API v1 路由入口。
- 建立单元测试和集成测试目录。
- 提供 `.env.example`，不提交真实密钥。

### 建议结构

```text
backend/
├── app/
│   ├── main.py
│   ├── api/v1/
│   ├── core/
│   ├── models/
│   ├── schemas/
│   ├── repositories/
│   ├── services/
│   ├── workflows/
│   ├── ai/
│   └── infrastructure/
├── migrations/
├── tests/
└── pyproject.toml
```

### 验收标准

- 后端服务可以启动和关闭。
- `/health` 返回正常状态。
- 可以连接 PostgreSQL。
- Alembic 可以创建和升级数据库版本。
- 测试命令可以运行。
- 未配置必要环境变量时给出明确错误。

## 3. FE-01：前端基础工程

### 工作范围

- 创建 `frontend` 工程。
- 配置路由、后台布局和 API 请求封装。
- 配置开发与生产环境变量。
- 建立通用加载、空状态和错误提示组件。
- 增加首页或系统状态页。

### 建议结构

```text
frontend/src/
├── api/
├── pages/
├── features/
├── components/
├── router/
├── types/
└── utils/
```

### 验收标准

- 前端开发服务可以启动。
- 路由和基础布局正常。
- 能请求后端 `/health`。
- 网络错误能反馈给用户。
- API 地址可以通过环境变量切换。

## 4. IT-01：基础联调

### 工作范围

- 配置本地跨域。
- 统一开发端口和 API 前缀。
- 验证前端到后端再到 PostgreSQL 的链路。
- 编写本地启动说明。

### 验收场景

1. 启动 PostgreSQL。
2. 执行数据库迁移。
3. 启动后端。
4. 启动前端。
5. 前端显示后端健康状态。
6. 后端日志包含请求 ID，前端错误信息可读。

## 5. 本计划不包含

- 用户登录和复杂权限
- LangGraph 工作流
- LLM 调用
- 内容任务业务表
- 图片和平台发布
