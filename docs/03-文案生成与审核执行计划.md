# 文案生成与审核执行计划

## 1. 目标

根据已选择的选题生成文章，保留所有版本，并通过人工审核完成通过、修改、退回或重新生成的闭环。

## 2. BE-05：文案生成后端

### LangGraph 流程

```text
load_selected_topic
→ generate_outline
→ generate_article
→ validate_article
→ save_article_version
→ wait_article_review
```

### 数据结构

```text
articles
├── id
├── content_task_id
├── selected_topic_id
├── status
└── current_version_id

article_versions
├── id
├── article_id
├── version_number
├── title
├── content
├── generation_instruction
├── source_type
└── created_at
```

`source_type` 可取：

```text
ai_generated
ai_revised
human_edited
```

### API

```text
GET  /content-tasks/{id}/article
GET  /articles/{id}/versions
POST /articles/{id}/regenerate
```

### 验收标准

- 一个内容任务只关联一个文章主体。
- 每次生成或修改都会产生新版本。
- 历史版本不可被覆盖。
- 当前版本通过 `current_version_id` 明确指向。
- 结构化输出异常不会写入残缺文章。

## 3. FE-04：文案编辑器

### 功能

- 查看文章标题和正文。
- 编辑并保存人工版本。
- 查看版本列表。
- 切换查看历史版本。
- 提交审核或要求重新生成。
- 离开未保存页面时给出提示。

### 验收标准

- 刷新页面不丢失已保存内容。
- 保存时能处理版本冲突。
- 生成中不能重复触发生成请求。

## 4. IT-04：文案生成联调

### 验收场景

1. 选题确认后生成文章。
2. 初稿保存为版本 1。
3. 人工编辑后保存为版本 2。
4. 版本 1 仍可查看。
5. 当前版本显示为版本 2。

## 5. BE-06：人工审核后端

### 审核数据

```text
review_records
├── id
├── content_task_id
├── article_version_id
├── decision
├── comment
├── reviewer_id
└── created_at
```

### 审核结果

```text
approve
reject
edit_and_approve
regenerate
```

### 工作流分支

```text
waiting_article_review
├── approve → completed
├── edit_and_approve → 保存人工版本 → completed
├── reject → revise_article → wait_article_review
└── regenerate → generate_article → wait_article_review
```

### API

```text
POST /articles/{id}/reviews/approve
POST /articles/{id}/reviews/reject
POST /articles/{id}/reviews/edit-and-approve
POST /articles/{id}/reviews/regenerate
```

### 可靠性要求

- 审核请求必须幂等。
- 重复点击不会让工作流恢复两次。
- LangGraph 恢复时节点重复执行不会重复创建版本。
- 审核记录不可覆盖或删除。

## 6. FE-05：审核工作台

### 功能

- 待审核任务列表。
- 查看和编辑待审文案。
- 填写退回意见。
- 通过、编辑后通过、退回和重新生成。
- 查看审核历史及对应文章版本。

## 7. IT-05：审核流程联调

### 必测场景

- 直接通过并完成任务。
- 人工修改后通过，产生新版本。
- 退回后 AI 按意见修订并再次等待审核。
- 重新生成后产生新版本。
- 等待审核期间关闭后端，重启后仍可继续。
- 重复提交相同审核请求不会产生重复数据。

## 8. 第一期 MVP 最终验收

- 完成内容任务、选题、文章和审核完整闭环。
- PostgreSQL 中能追溯每个版本和审核决定。
- LangGraph 工作流可以可靠暂停和恢复。
- 前端能明确显示当前阶段、失败原因和下一步操作。
- 暂不依赖图片服务或内容平台接口。
