# 项目范围与分期

## 1. 项目目标

建设一套基于 LangGraph 1.x、FastAPI 和 PostgreSQL 的 AI 自媒体内容生产系统，首先服务 AI 编程培训业务。

最小业务闭环：

```text
创建内容任务
→ AI 生成候选选题
→ 人工选择选题
→ AI 生成文案
→ 人工审核
→ 退回修改或确认完成
```

## 2. 分期范围

### 第一期：内容生产 MVP（P0）

- 内容任务管理
- 候选选题生成
- 人工选择选题
- 文案生成
- 文案版本管理
- 人工审核、退回和重新生成
- LangGraph 暂停、持久化和恢复
- PostgreSQL 业务数据持久化

明确不做：图片、公众号、自动发布、定时任务、运营分析和复杂权限。

### 第二期：小红书内容包（P1）

- 文案压缩为 3～5 页视觉内容
- 图片页面脚本
- 图片生成和单张重生成
- 人工上传替换
- 小红书标题、正文和标签适配
- 内容包预览与下载

### 第三期：多平台内容（P2）

- 微信公众号文章适配
- 富文本正文与封面
- 平台内容预览
- 平台账号配置
- 手动发布状态管理

### 第四期：发布自动化（P3）

- 预约和自动发布
- 发布前审批
- 幂等控制与失败重试
- 平台状态同步
- 内容日历

### 第五期：数据运营（P4）

- 阅读、点赞、收藏和评论指标
- 内容效果评分
- 用户偏好学习
- 历史选题去重
- 模型成本与效果分析
- 提示词 A/B 测试

## 3. 前后端边界

### 后端负责

- 业务规则和数据持久化
- LangGraph 工作流编排
- LLM 和图片模型调用
- 审核状态和版本管理
- 平台适配与外部发布
- 权限、审计和任务状态

### 前端负责

- 运营工作台和流程导航
- 表单输入、内容编辑与预览
- 人工选题和审核操作
- 工作流进度展示
- 错误反馈和版本对比

### 前后端契约

- 只通过 `/api/v1` 接口通信。
- 耗时任务返回任务 ID，不长时间阻塞 HTTP 请求。
- 状态值由后端统一定义，前端只做展示与操作映射。
- API 数据结构变更必须同步更新接口文档。

## 4. 长期扩展接口

第一期只定义边界，不提前实现后期能力：

```text
LLMProvider       # 替换或增加大模型
ImageProvider     # 接入图片生成服务
ChannelAdapter    # 增加内容平台
MetricCollector   # 增加平台指标采集
```

## 5. 模块职责

- `api`：请求解析和响应，不承载业务规则。
- `services`：业务用例和规则。
- `workflows`：LangGraph 流程和状态路由。
- `repositories`：数据库访问。
- `ai`：模型网关、提示词和结构化输出。
- `frontend/features`：按业务功能组织前端代码。

## 6. 一期完成标准

- 用户可以从前端创建内容任务。
- 系统能生成多个候选选题并等待人工选择。
- 选择后能生成文章并保存版本。
- 用户可以通过、编辑后通过、退回或重新生成。
- 服务在等待审核时重启，任务仍可继续。
- 所有关键操作都有数据库记录和可读错误信息。
