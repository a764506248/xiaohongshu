# 内容任务与选题执行计划

## 1. 目标

让运营人员创建内容任务，调用 AI 生成多个候选选题，并人工选择一个选题进入下一阶段。

## 2. BE-02：内容任务后端

### 核心数据

```text
content_tasks
├── id
├── title
├── requirement
├── target_audience
├── status
├── current_stage
├── created_at
└── updated_at
```

### 第一期状态

```text
draft
generating_topics
waiting_topic_selection
generating_article
waiting_article_review
completed
failed
```

### API

```text
POST  /api/v1/content-tasks
GET   /api/v1/content-tasks
GET   /api/v1/content-tasks/{id}
PATCH /api/v1/content-tasks/{id}
```

### 验收标准

- 能创建、查询和更新内容任务。
- 状态转换经过服务层校验。
- 数据库异常返回统一错误结构。
- 核心服务具有单元测试。

## 3. FE-02：内容任务前端

### 页面

- 内容任务列表
- 创建内容任务
- 内容任务详情

### 功能

- 按状态筛选任务。
- 显示当前工作流阶段。
- 创建任务并跳转详情。
- 展示加载、空数据和失败状态。

## 4. IT-02：内容任务联调

### 验收场景

1. 前端创建内容任务。
2. 后端保存到 PostgreSQL。
3. 刷新后任务仍然存在。
4. 列表和详情页状态一致。

## 5. BE-03：LLM 基础网关

### 工作范围

- 定义模型无关的 `LLMProvider`。
- 第一阶段只实现结构化文本生成。
- 支持超时、有限重试和错误转换。
- 记录模型、耗时、token 用量和调用状态。
- 提示词与业务节点代码分离。

### 边界

- 业务服务不得直接依赖特定模型 SDK。
- API 密钥只从安全配置读取。
- 结构化结果必须先校验再写入数据库。

## 6. BE-04：选题工作流

### LangGraph 流程

```text
load_task
→ generate_topics
→ validate_topics
→ save_topics
→ wait_topic_selection
```

### 候选选题数据

```text
topic_candidates
├── id
├── content_task_id
├── title
├── summary
├── target_reader
├── reason
├── score
├── status
└── created_at
```

### API

```text
POST /content-tasks/{id}/generate-topics
GET  /content-tasks/{id}/topics
POST /content-tasks/{id}/select-topic
POST /content-tasks/{id}/regenerate-topics
```

### 工作流持久化

- 使用 PostgreSQL checkpointer。
- `thread_id` 与内容任务及工作流运行记录关联。
- `wait_topic_selection` 使用人工中断。
- 工作流 state 只存业务 ID 和少量路由数据。

## 7. FE-03：选题选择页面

### 功能

- 展示候选选题卡片。
- 展示标题、概要、目标读者、推荐理由和评分。
- 选择一个选题。
- 填写补充要求并重新生成。
- 显示生成中和失败重试状态。

## 8. IT-03：选题流程联调

### 验收场景

1. 用户点击生成选题。
2. 任务进入 `generating_topics`。
3. 候选选题写入数据库。
4. 工作流暂停并进入 `waiting_topic_selection`。
5. 用户选择选题。
6. 工作流从暂停点恢复。
7. 已选择选题被锁定，重复提交不会造成重复恢复。

## 9. 本计划不包含

- 文章生成
- 图片生成
- 热点网络检索
- 多用户偏好学习
- 平台发布
