# AI 自媒体运营系统执行计划

本目录用于管理项目的分期执行计划。项目采用前后端分离架构，每次开发只执行一个明确的任务单元，完成后再进入下一单元。

> 如果你是第一次阅读本项目，不建议从执行计划开始。请先看“推荐阅读路线”和“常用术语”，再进入具体阶段文档。

## 常用术语

| 术语 | 项目中的含义 |
|---|---|
| 内容任务 | 一次从选题到最终内容包的完整生产任务 |
| 候选选题 | LLM 生成、等待运营人员选择的主题方案 |
| 文章母稿 | 与发布平台无关的 Markdown 长文 |
| 文章版本 | 每次 AI 生成、AI 修订或人工编辑后的不可变记录 |
| 人工中断 | LangGraph 暂停执行并等待用户选择或审核 |
| `thread_id` | LangGraph 查找该次执行 checkpoint 的标识 |
| checkpoint | 工作流执行状态的持久化快照 |
| 内容包 | 小红书标题、正文、标签和 3～5 张图片的集合 |
| 图片页面 | 内容包中的一页，例如封面、核心观点或行动建议 |
| 图片版本 | 页面每次重新排版、重新生成或人工上传产生的记录 |
| Mock 模型 | 不访问外部 API、用于自动化测试的固定输出模型 |

## 单项执行规则

- 一次只执行一个编号任务，例如 `BE-02` 或 `FE-03`。
- 后端接口完成并自测后，再实现依赖它的前端任务。
- 每组前后端任务后必须执行对应的 `IT` 联调任务。
- 未达到验收标准，不进入下一个功能阶段。
- 后续功能通过既定扩展接口接入，避免提前实现暂不需要的模块。

### XHS MCP 自动发布

后台支持通过本机 `xhs-mcp` 服务执行小红书图文发布。该能力基于 Puppeteer，属于非官方页面自动化，请控制发布频率并自行承担账号风控风险。

1. 准备 Chromium 并启动 MCP 服务：

   ```bash
   npx xhs-mcp browser
   npx xhs-mcp mcp --mode http --port 3000
   ```

2. 在另一个终端完成登录并确认状态：

   ```bash
   npx xhs-mcp login --timeout 120
   npx xhs-mcp status
   ```

3. 后端 `.env` 配置：

   ```env
   XHS_MCP_URL=http://127.0.0.1:3000/mcp
   XHS_MCP_TIMEOUT_SECONDS=300
   ```

4. 在任务的“多平台运营”页面添加账号，发布方式选择“XHS MCP 自动发布”，点击“检测登录”。创建发布任务并审批后，后端会调用 `xhs_publish_content`。

安全限制：MCP 地址必须是本机回环地址；发布图片必须来自 `backend/storage/images`，后台不会向 MCP 传递用户填写的任意 URL 或任意本地路径。
